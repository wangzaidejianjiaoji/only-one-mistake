# A 的架构与边界

结构为 Codex 接入层、确定性事件处理、SQLite 问题台账、经验检索和验证器。语义理解与报告撰写由活跃宿主模型完成，worker 只整理本地队列，不调用独立模型。

## 目录

- `src/companion.ts`：采集、去重、问题状态、经验验证、精确失败路径检查、复盘请求和版本管理。
- `src/user.ts`：按当前工作区或最近 Git 根目录路由用户状态，迁移既有项目状态。
- `src/cli.ts`：hook、context、report、summary、memory、coverage 等接口。
- `src/transcript.ts`：转录增量偏移游标、部分行处理与格式缺口。
- `src/store.ts`：SQLite 事务和 JSON 记录；`src/normalize.ts`：事件归一、环境指纹和基础脱敏。
- `skills/evolveflow-companion/`：唯一附带技能，指导宿主查看证据和提交报告。
- `tools/`：用户/项目安装、检查、打包和可复跑的证据试点。

## 数据与决策

问题从发现、调查、验证转入可复用状态。执行类经验必须引用捕获的成功证据；历史转录不能伪装为实时执行证据。项目级启用还需相似场景和负例证据。明确用户纠正可作为范围受限的非执行记忆。

用户状态位于 `<CODEX_HOME>/evolveflow/projects/<工作区哈希>/state`。经验限定会话或项目，环境变化需要重新验证。迁移代码路径不会自动改变历史环境证据；旧路径记忆不能强行改写为新环境的有效结论。

普通回合在 Stop 节点最多请求一次复盘；记录开始复盘时的队列快照。完成只能关闭该快照的普通上下文，不能关闭新消息或未解决的工具失败。中断优先，行政操作排除在自学习之外。

转录采集有增量游标及事件去重；来源对话的语义复盘还需先比较来源检查点与内容。同一报告直接重复提交仍会生成新版本，不能将来源快照幂等试点说成全场景语义去重。

## 信任和覆盖

宿主 hooks 需要审阅信任，安装器不修改信任。只能监控宿主公开的上下文，不能读取隐藏状态；缺事件、未知格式、无退出状态都要报告 coverage。文件安装、显式适配器回放与原生宿主触发是三种不同证据。
